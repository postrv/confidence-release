# Artifacts provider preflight

The executable preflight uses a fresh random namespace and repository containing inert text and binary files. It accepts no existing repository name or remote. It sends the same fixed-old/fixed-new Git receive-pack bytes used by the privileged publication adapter, observes the remote ref separately, and fetches the raw Git objects back into an independent repository. A live PASS is a bounded provider observation; it does not establish the other deployment gates.

Run with the repository's installed dependencies:

```sh
node --import tsx scripts/provider-preflight.ts --probe-wrangler --out preflight-output/oauth-readiness.json
node --import tsx scripts/provider-preflight.ts --self-test --out preflight-output/self-test.json
node --import tsx scripts/provider-preflight.ts --run --out preflight-output/provider-preflight.json
node --import tsx scripts/provider-preflight.ts --run --use-wrangler --out preflight-output/wrangler-preflight.json
```

The default live path requires `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` in its environment. Supply the credential through your private shell or secret manager; do not put it in the command, source, output or shared run guide. The API token must authorize Artifacts read/write on the selected account. With missing credentials, the command records BLOCKED and exits 2 before any remote mutation. No `--run` flag also records BLOCKED without remote calls. Self-test executes only owned local mocks and Git object/packet checks and reports SELF_TEST_PASS, never provider PASS.

`--use-wrangler` explicitly selects the existing Wrangler OAuth login. It privately captures `whoami --json`, checks `artifacts:write` and confirms that `CLOUDFLARE_ACCOUNT_ID` belongs to that login. If no account is configured, exactly one account must be available; multiple accounts require an explicit selection. A missing permission or account mismatch records BLOCKED before token retrieval or mutation. Only after those checks pass does the script privately capture the installed CLI's `auth token --json` output and use the token in memory for the same fresh-resource checks. Environment API tokens and global keys are excluded from that subprocess so this option consistently selects the existing login. The default API-token path remains separate and does not invoke Wrangler.

Wrangler stdout and stderr are piped privately, disk logging and telemetry are disabled, and the report includes only allowlisted account/scope facts and numeric error codes. Ordinary OAuth renewal of the existing login is permitted; Wrangler maintains its existing private credential store. The subprocess runs noninteractively and never initiates a new browser login, requests additional scopes or changes account membership. Unavailable renewal remains BLOCKED. The script never exposes a token or writes captured token output to a report or CLI debug log.

The optional `--probe-wrangler` path runs the installed CLI's `whoami --json` and read-only namespace listing under the same private subprocess protections. It records authenticated/scope facts and numeric API errors while omitting personal identity, credentials and arbitrary CLI diagnostics. It always leaves the conditional-update gate BLOCKED because listing does not test publication. The original probe lacked `artifacts:write` and returned code 10000. The user-approved permission refresh on 5 October resolved that access; the historical report remains unchanged.

The live sequence creates `confidence-preflight-<random>` and `owned-ref-check-<random>`, then checks:

1. The returned HTTPS remote identifies exactly the selected account and freshly created resources, and the main ref is empty.
2. A baseline B can be installed and its raw commit, tree, blobs, executable mode and binary REST file bytes round-trip exactly.
3. A child N is installed with B fixed as the expected old head. Repeating B/N preserves N; the report distinguishes a rejected stale expected-old from an idempotent acknowledgment.
4. Two child commits race using the same frozen base N. Both outcomes must be observed, exactly one acknowledged update may win, and the subsequently observed head must match that winner.
5. Retrying the loser retains its original expected old head and fails. The winning source round-trips exactly.
6. A fresh fork reflects the advanced canonical head. An exact older baseline can be installed on its independent work ref; an unpublished repair source can also be transferred and read back without advancing either main ref.
7. A revoked read token is rejected by Git. Canonical and fork token inventories confirm revocation before their journaled deletions.

The report retains actual request/response SHA-256 digests, frozen B/N values, HTTP status, ref observations, exact object digests, source digests, Git revision when available, dependency versions and UTC observation times. Credentials and arbitrary provider messages are omitted. Each invocation writes its report even on a failed or blocked run. Exit 0 means PASS or explicitly local SELF_TEST_PASS; exit 1 means a failed/uncertain live check; exit 2 means the live gate was not attempted.

Requests have bounded response sizes, fixed HTTPS destinations, redirect rejection and 20-second timeouts through body consumption. Timed-out mutations are not blindly repeated or claimed aborted. Each namespace/repository creation records `MAY_HAVE_DISPATCHED` durably before its POST. Every Git update records its immutable old/new heads, ref and request digest before dispatch. A missing response becomes `UNKNOWN`, with repository `created: null` and `cleanup: RECONCILIATION_REQUIRED` when creation is uncertain; the intended names remain for manual reconciliation. Serialized, fsynced report replacement prevents overlapping race saves from losing an earlier intent. The script does not mutate an unverified repository. The local self-test simulates a resource being created followed by a lost response and verifies the dispatch fence and this uncertainty classification.

The self-test also checks that missing Artifacts scope, account mismatch and ambiguous account selection prevent token retrieval; a verified mock login selects its exact token only in memory; arbitrary CLI errors, identity fields and token-shaped diagnostics are omitted; global API keys are rejected; default API-token authentication skips Wrangler; and the private subprocess disables logging and interactive login while preserving ordinary credential renewal. These tests use synthetic credentials and perform no provider calls.

Cleanup verifies the acknowledged repository ID and its run-specific description, revokes its active tokens, then requests deletion. `--keep-repo` retains only the newly created repository while still revoking its tokens. Repository deletion is an acknowledged asynchronous request, not a claim of completed remote erasure. The documented REST API has no namespace-delete route; the empty test namespace remains. Cleanup uncertainty is visible in the report and does not become an erasure claim.

Keep `CONDITIONAL_PUBLICATION_VERIFIED=false` until genuine current-source live REST/Git and Worker-binding reports pass for the intended provider/account/namespace. Configuration rejects missing or duplicated required checks, different accounts/namespaces, altered source inputs and missing native deployment identity. A REST/Git passing run does not establish deployed Worker binding behaviour, process termination, network interception, model execution, OIDC integration or portable receipt verification. Those have separate conformance checks. The preflight does not change deployment configuration or enable publication automatically. See the [integration runbook](ARTIFACTS_INTEGRATION.md) for the binding harness and release contract.

The installed Wrangler command surface was checked at version 4.147.0: `artifacts namespaces` lists/gets namespaces; `artifacts repos` supports create/get/list/delete and repo-scoped token issuance. Namespace creation and raw object inspection use the documented [Artifacts REST API](https://developers.cloudflare.com/artifacts/api/rest-api/); Git transfer uses the documented [smart HTTP protocol](https://developers.cloudflare.com/artifacts/api/git-protocol/). These routes mirror the [Workers binding](https://developers.cloudflare.com/artifacts/api/workers-binding/). This script imports the application's receive-pack encoder, report parser and remote validator so the provider spike checks that adapter's actual wire shape.
