## Narration

### 0:00-0:35 - The wrong value

Confidence helps teams turn parallel agent work into a release they can explain, review and verify independently. The problem is concrete: a write acknowledges a new value, but the next read returns the old one. Three changes can combine cleanly in Git and still violate the useful goal. Our goal is fresh writes, useful caching and an accessible saved-value status together. The label on screen distinguishes the current walkthrough from retained Cloudflare evidence.

### 0:35-1:25 - Three kinds of fact

Agent A adds a cache. Agent B simplifies writes. Agent C exposes the saved value accessibly. Confidence keeps each assignment, exact starting source and immutable submission. It also distinguishes what an agent says it intends from what source it actually submits and what the checker observes. The native pilot retained three real model sessions with overlapping work. A local reproduction uses concurrent subprocesses with predetermined edits instead; it needs no account or model call. These are different demonstrations, and we do not turn one into evidence for the other.

Look at the recorded start and stop times, not just three cards on a screen. Parallelism is a fact to observe, not a label to assume. Each contribution retains its own source identity and bounded authority.

### 1:25-2:25 - Explain the interaction

The baseline passes the declared freshness probe. A's change alone passes it, and B's change alone passes it. Their combined source fails the same probe: the trace warms a cache, acknowledges the write and then reads the stale value. This is a small designed interaction, not a claim to understand every program or prove universal independence.

The important product moment is that the failure is connected to its actual source, selected contributions and observed trace. A reviewer does not have to infer the problem from a green branch and a clean merge. Ordinary CI with the same effective check can detect this bug too. Confidence's addition is the connected explanation, repair context and release decision that follow from that observation.

### 2:25-3:40 - Preserve the useful work

Repair starts from the exact failed candidate and receives the counterexample. It is not a new vague instruction to make the tests green. Turning the cache off could hide the stale read while discarding Agent A's useful work. The repair must keep cache benefit and accessible saved status alongside freshness.

The retained native journey included earlier failures. A repair passed eight sequential cases, but an independent overlap probe exposed stale cache repopulation. The human chose to fix concurrency before publication. The successor, identified on screen as 15456806, passed all nine final protected cases and independent source review. Those failures remain part of the history; we do not rewrite them as a smooth first attempt.

The resulting lineage connects the original useful contributions, failed source, repair and exact successor. These are finite declared checks, not exhaustive correctness. The proof is easier to inspect because each observation names the source and requirement it actually covers.

### 3:40-4:55 - A human decision with an identity

Passing checks are not permission to publish. The reviewer sees the changed files, complete source, candidate commit, expected canonical head and named evidence. Approval binds that exact proposal and is consumed by its publication operation. A different head, expired proposal or changed review input needs a new decision.

The historical Cloudflare pilot advanced one canonical Artifacts ref to the approved source. Its receive-pack acknowledgement, observed ref and source readback are distinct facts. The current deployment has publication disabled; viewing the record is not publishing again. Its original receipt keeps its original platform and source identities.

Recovery follows the same rule. A lost response means unknown, not automatically failed or cancelled. Preserve the original command or operation and inspect its outcome before another intent. The comparison later exposed a stale-revision controller rejection; that failure stayed visible while a separate zero-model reconciliation completed evaluation and cleanup.

### 4:55-6:10 - The decision leaves the service

Now we verify outside the web application. These three files are a new, safe synthetic local export, not the production receipt redacted or silently replaced. The public trust file identifies this example; selecting it does not establish trust in the Cloudflare service.

The native Rust verifier checks integrity, authorization, observed publication, continuity and source identity separately. All six positive facets pass. The logical receipt digest matches the packet's manifest. After compilation this command needs only the three JSON inputs and can run with networking disabled.

We then change one signature in a disposable copy. The verifier rejects it with BAD_SIGNATURE, and the original example is unchanged. That shows the boundary is checked, not merely described. It does not prove the remote head is still current or that the program is generally correct. Trust selection and operator control remain explicit assumptions. Judges can reproduce this step without a Cloudflare account, secret or paid model run.

### 6:10-7:10 - Tools in the actual loop

We also measured real coding with Narsil and Interlinked together versus neither, using the same task, initial source, model, protected checker, resources and four-call allowance. Both results passed nine protected checks. With both tools, coding and ingestion took 120.612 seconds and one model call; without them, 258.371 seconds and two calls. Narsil's advisory was included in the actual prompt. Interlinked's preview observed coherent source and no blocking findings; this episode does not show it repairing a defect.

The enabled full workflow was longer: 1,106.485 seconds versus 631.147, including deployment and the operator pause for recovery. The verified-response estimates total about two and a half cents, but account billing and exhaustive inventory coverage remain unknown. One designed task, one sequential episode per arm and both tools changing together do not establish a general or individual-tool performance advantage.

### 7:10-8:00 - The product boundary

The current product also has project management, source inspection and scoped collaboration roles. Login through Access is separate from project permission. Invitations, revocation, audit and last-owner protection support collaboration; independent live-person acceptance, teams and reviewer quorum are not claimed. Imported source can be inspected and configured, but generic imported execution and publication remain separate capabilities.

The strongest thing to remember is one connected record: parallel work, an actual interaction, goal-preserving repair, exact human decision and portable verification. The packet makes that supported path runnable and keeps the limitations beside the proof. Confidence is not a universal correctness oracle. It is a working collaboration prototype that makes a particular release explainable and independently checkable.
