## The machine-readable index

evidence/index.json (retained private reference; unavailable in this source distribution) associates selected original reports
with their exact file byte SHA-256 and size. Paths in that index are repository
relative. File-byte digests are distinct from logical receipt, manifest, evidence
or proposal digests embedded in those files.

Each entry records its question, sample class, cohort, measurement interval,
result/check trust level and limitations. `readableSourcePins` points to the
original fields that identify code, tools, images, model and checker; these pins
must not be silently replaced with today's versions. The index is a guide to
retained observations, not a new signature, independent trust root or re-run.

The native publication entry binds the original private receipt/audit file
hashes and logical receipt digest from the retained checkpoint. It deliberately
does not turn a Markdown narrative into a downloadable production proof.
Private original bytes, contact information, credentials and operator state
are not part of the public example.

## Read the trust level correctly

**Authority-reported** means the application retained the outcome for its exact
candidate/plan. The original two-arm comparison exposes these reports and
digests; this handover does not claim a new independent signature audit of that
pair.

**Independently verified checker signatures** in the new confirmation means
nine retained signatures were checked against authenticated scoped public trust
bound to enrollment. The source/image/checker/job association and 27 object byte
digests were checked separately. Operator-selected trust assumptions remain;
this is not a portable publication receipt or universal root of trust.

**Offline portable verification** requires the exact receipt, independently
selected trust and checkpoint attestation. The safe packet uses synthetic local
keys, scopes and scripted approval. It proves this example can be replayed and
tampering rejected; it does not assert Cloudflare identity, independent-human
acceptance or the current canonical head.

**Local/component** and **mocked-boundary** evidence has weaker environmental
scope than native execution. A mocked operation count is not a provider bill.
A fixed invalid proposal caught by a tool is not evidence that a model made a
better proposal.

## Preserve the whole result

The original both-tools arm remains `INCOMPLETE` at its first controller
termination, followed by separately reviewed zero-model evaluation/cleanup.
Its longer full workflow includes the operator pause. Both failed read-only
export attempts and the successful repeat remain historical observations;
neither restarted a paid coding episode.

The fresh confirmation is a separate result, not a replacement denominator.
It had no live stale rejection. Deterministic fault tests establish bounded
recovery behavior; the successful live run establishes clean completion.
Interlinked reported no blocking findings in both native tool episodes; no
defect-repair benefit was demonstrated. Narsil context was actually included,
but index coverage was incomplete.

Known new calls have matched usage responses. The bounded global inventory
still has uninspected historical objects; invoices remain unknown. Keep response
estimates, conservative admission ceilings, internal reservation units and
actual billing in separate fields.

## What stays outside the submission front door

Archived development material (retained private reference; unavailable in this source distribution) preserves earlier design,
research, preflights and superseded operational checkpoints. It explains why a
direction was chosen; it is not the current release status. The two unchanged
historical throughput/research records preserve their original relative-link
context and claims as written at the time.

Ignored `.pilot/`, `demo-output/`, dependency trees, caches, raw sessions,
private keys and operator credentials are not source-distribution inputs.
Archive placement inside this private repository does **not** make material
safe to publish: the future clean public repository needs its own privacy,
license, history and source-archive review. Promoted sanitized JSON and the
synthetic verifier example can be reviewed independently of private exports.

Use [claim boundaries](judge-packet/CLAIMS.md) beside the demo and
[current release status](RELEASE_STATUS.md) for the last observed runtime.
No evidence here supports arbitrary imported-repository execution, universal
correctness, airtight security, general model superiority or sustained scale.
